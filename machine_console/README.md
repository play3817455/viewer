# Gundam Machine Console

This project is a focused mech preview console. It loads one mech into an empty preview space, plays a manually selected MRB clip, and lets you mount manually selected weapon models with editable transforms and bone bindings. Per-mech profiles save the reviewed parameters, weapon IDs, separate battle/kill-log icon IDs, effect paths, and mount transforms.

The Direct3D executable is `build/Release/GundamMachineConsole.exe`. Select the unpacked `GundamOnline/unpackdat` root, load a mech from `ms_bind.csv`, then use the resource tabs to inspect its model, motion, weapon, and effect resources. Numeric IDs are not converted into effect paths unless the client evidence confirms that relationship.

The effect tab indexes FX DXG/VRA/DDS plus the PNG/TGA images under `fx/`. For an explicit `fx/.../PP_*.vra`, it reads every Sprite/Particle node whose referenced image can be resolved, composites a deterministic approximate frame, and adds other direct references to the list for inspection. The preview time slider uses the PP `Header.frame` range and approximates plug windows, particle count/cycle/lifetime, position, velocity, acceleration, scale, Z-axis rotation, and fade in/out. If the PP contains Model nodes but no readable Sprite/Particle image, it opens the first Model geometry as a static preview. The preview still does not reproduce the client's exact event schedule, Work animation, 3D billboard orientation, UV animation, or blend modes. The existing mount control still mounts one selected PP image as a transformable plane with utility alpha blending. FX catalog rows also show their `fx.csv` comment when present.

DXG preview follows the paired VRA mesh names and draws only meshes with a `lod0` material binding, applies VRA UV0 offsets, and respects `no_render`. Unpaired raw DXG files remain viewable without materials. Texture recovery includes evidence-based directory-ID and legacy BST repairs, item prefix/variant repairs, and clearly labeled preview fallbacks for `item/12/0107` and `item/04/8417`; the latter uses 8413's same-material 01/02 texture siblings when the 8417 texture directory is absent. Map-specific stale keys and approximate fallbacks are labeled separately: F14/U02/U09 name repairs, F16 terrain and grass-mask previews, U17 PSD-to-DDS mappings and hazard-stripe preview, U24 cliff rock-family previews, object/09 YS textures from object/60 plus labeled local building previews, and object/22 container/U09 dross and same-name mix-mask fallbacks. FX preview repairs the official `MT_05_208_02.png` prefix typo to the sibling `PT_05_208_02.png`. Cross-format same-stem images are used only when the candidate is unique or all candidate bytes match; ambiguous resources stay unresolved.

Profiles are stored beside the executable in `machine_profiles/<mech-id>.ini`. IDs and resource paths with unknown mappings stay manual and are labeled as such. UE experiments under `ue/` are archived and are not part of the active preview workflow. This project does not modify `gundamres` or `iconmatch`.

## Resource coverage audit

Run `cmake -S . -B build -A x64` once, then `cmake --build build --config Release --target GundamMachineConsole` from this directory. Run `python tools/audit_viewer_assets.py <official-unpackdat> --output docs/viewer-asset-coverage.json` from this directory to refresh the resource audit. The report inventories DXG block boundaries, common model-to-attribute VRA filename pairs, DXG mesh-to-VRA material bindings, VRA `s_base`/`s_mix`/`s_gloss` texture links, and Sprite/Particle image references in FX PP files. For missing or ambiguous textures, it records representative DXG → mesh/material slot → VRA chains so a missing image can be traced to the exact resource binding. VRA strings are decoded as UTF-8, then CP932, then the Windows active code page; this matters for legacy full-width whitespace in resource paths. Texture recovery uses the same rules as the viewer: exact and whitespace-trimmed paths first, then deterministic same-folder filename normalization for repeated dots, embedded duplicate suffixes, one-digit sequence numbers, and an alternate image extension; evidence-based chara BST and bidirectional item EM/ET aliases are constrained to their resource directory IDs. The `item/04/8413` saber repair additionally uses the paired VRA geometry to identify an exact variant DDS. The `item/12/0107` fallback uses the exact model 01/02 geometry's existing base image when its requested 04C–10C image is absent, and is reported separately. Map-specific repairs and approximate preview fallbacks are separately classified in the audit; same-folder evidence is required for stale map-name fixes and explicitly scoped cross-directory fallbacks are labeled. A unique basename or byte-identical basename candidates are the final fallback. If the original extension has no match, a unique or byte-identical same-stem image with another supported extension can also be used. Differing same-name candidates remain unresolved.
