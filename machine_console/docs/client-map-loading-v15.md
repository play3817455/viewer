# v15 客户端地图加载逆向记录

本记录只写已由客户端静态分析或解包文件直接确认的行为。分析对象由 `ida-pro-mcp` 健康检查确认：`unpacked/GundamOnline_CHINA_v15.exe.i64`，模块 `GundamOnline_CHINA_v15.exe`，imagebase `0x400000`。

## 地图表读取

- `sub_458730`（`0x458730`）调用 `sub_458610` 读取地图配置；`sub_458610` 将资源键 `0x0A000001` 解析为表资源，并调用通用表读取器 `sub_AEFD80`，行回调为 `sub_457770`。因此 `sub_457770` 是地图表行解析器，不是场景目录扫描器。
- `sub_457770`（`0x457770`，大小 `0xE94`）读取一个地图配置记录。函数先读取记录索引 0；若为非零且不等于 35，继续组装配置。
- 记录索引 1–6 和 8–9 各自前置 `world/field/`，索引 7 前置 `world/sky/`，然后把各自值复制到字符串字段。路径类型及索引来自该函数的反编译，不是根据资源命名习惯推测。
- 同一函数继续读取索引 `0x0A` 到 `0x4E` 的数值/字符串配置，其中多个字段保存为向量或浮点数。完整字段语义仍需与 `settings/map.csv` 表头逐列对应，不能仅按结构偏移命名。
- `unpackdat/settings/map.csv` 的记录 `100102` 明确给出：`F01/F01_01_grd.vra`、`F01/F01_02_obj.vra`、`F01/F01_02_2ndbox.vra`、`F12/attr/SZ_F12_ht_sky01A.vra`、`F01/F01_11_hit.dxg`、模板 `F01/F01_%02d_area.vra` 和数量 `10`。这与 `sub_457770` 的多个字段路径槽相互对应。

## VRA 场景对象解析

- `sub_A83A70`（`0xA83A70`）是地图资源回调之一：它检查当前资源路径是否以 `grd.vra` 结尾。是地形资源时转到 `sub_ABA7A0`；其它资源走 `sub_ABB8E0` 对象处理路径。因此客户端会区分地形 VRA 与普通摆放对象，不能把它们无条件当成同一种 placement 列表处理。
- `sub_ABA7A0` 读取 `Env` 与 `Models` 组并调用 `sub_ABA4F0`；对象路径中的 `sub_ABB8E0` 进一步进入 `sub_ABB420`。两条加载分支有不同工作，完整渲染/碰撞下游尚未完成追踪。
- `sub_AB4BD0`（`0xAB4BD0`）按对象字段名解析 VRA 记录，包括 `name`、`category`、`pos`、`rot`、`scale`、`renderid`、`shadow`、`castshadow`、`physics`、`lightid`。
- 该解析器现场组装属性资源路径：`world/field/` + category + `/attr/` + name + `.vra`。它把 `pos` 写入对象结构偏移 `+0x1C..+0x24`，`rot` 写入 `+0x28..+0x34`，`scale` 写入 `+0x38..+0x40`，renderid 写入 `+0x44`，lightid 写入 `+0x48`。
- 同一函数把 `shadow`、`physics`、`castshadow` 分别合并到 `+0x4C` 的 bit 0、bit 1、bit 2。这是字段标志的静态证据；物理位如何进入碰撞/命中查询仍需沿后续消费者追踪。
- `sub_ABA2D0`（`0xABA2D0`）递归处理 `Group`，并把普通对象交给 `sub_AB4BD0` 解析。`sub_ABA240` 遍历对象记录并交给 `sub_AB5B60` 处理。
- 这证明客户端的 VRA 对象记录不仅是几何路径列表；位置、旋转、缩放及若干渲染/物理标志都属于对象定义。`lightid` 的最终渲染作用和 `physics` 到碰撞世界的完整消费链还未追完。

## 当前轻量预览器与客户端的已知差异

- `main.cpp::LoadFieldScene` 只扫描指定 `world/field/<code>` 目录中的 `*_grd.vra` 与 `*_obj.vra`，不会按 map ID 解析 `map.csv`。
- 当前实现没有纳入地图记录指定的 `_2ndbox.vra`、`_hit.dxg`、`_area.vra`、地图效果与遮挡资源，也没有按地图记录选择天幕 VRA。因此“隧道/建筑缺失、物体悬空”不能简单归因于单个模型；地图装配输入本身就与客户端地图记录不同。
- `SceneVraDoc` 当前解析对象位置、旋转、缩放和三个标志，但未保留 `lightid`。它还需用真实资源继续验证嵌套 Group、缺失对象及不同字段语法的覆盖率。
- 这里的差异是代码对照结论，不等于已确认所有缺件的唯一原因。坐标系、旋转解释、客户端资源调度/LOD、碰撞/命中网格、动态对象与显示条件都还要分别取证。

## 已确认与未确认的边界

- 已确认：目标客户端从地图配置记录取得资源路径；地形 `.grd.vra` 和普通对象 VRA 进入不同回调分支；普通对象属性路径按 category/name 生成；位置、旋转、缩放、renderid、lightid 及 shadow/physics/castshadow 位被解析进对象数据。
- 尚未确认：地形/对象 `Models` 遍历后如何与流式回调分工；placement 的 `physics` 如何进入走行碰撞、是否还依赖独立 hit 文件；`_2ndbox` 在运行时的遮挡/碰撞/模型作用；area 文件编号与加载范围的精确规则；`hit.dxg` 的碰撞/命中消费；动态加载半径与 LOD 条件；客户端坐标基底和当前预览器变换是否一致。
- 因而下一轮应继续沿 `sub_A83A70` 的地形/对象两个分支，追 `sub_ABA7A0`、`sub_ABB8E0` 与 `sub_A83290` 的下游消费者，再把某个具体缺失隧道和悬空建筑绑定到资源记录与变换。现在还没有依据把问题归结为“再多扫几种文件”或“统一加一个坐标偏移”。

## 当前状态

此文件保留地图加载的静态取证记录，仅作背景资料。当前工具目标已收敛为机体预览空间：模型、动作、手动挂载武器与效果；地图装载不是预览前置条件，也不是当前实现主线。
