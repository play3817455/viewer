# ASD / MAN 客户端反汇编结构复核

范围只使用正式资源根 `机动战士敢达Online/GundamOnline/unpackdat/` 与项目指定 v15 IDB（`GundamOnline_CHINA_v15.exe.i64`，ImageBase `0x400000`）。本文把由读取指令直接证明的字段与依据样本统计的具体变体分开；未知枚举不按名字猜测。

## 结论

- **ASD 是无头、定长24字节的动作时间事件表。** 每条记录由一个 float 时间、一个 DWORD 类型码和四个 DWORD 参数组成；客户端把记录按时间区间执行，负时间记录终止扫描。8,913份官方 ASD 均为24字节倍数，逐份都含负时间结束记录。
- **MAN 是 `0nam` 容器，承载按骨名关联的浮点曲线。** 客户端检查版本和记录类型，读取曲线点数、名称游标和多个 `(时间, 数值)` float 对，再通过一个控制器按时间插值。37份官方 MAN 都是80字节、单记录的同一变体。
- `.asd/.man` 资源加载函数本身只请求文件。包体解释分别在 ASD 时间事件执行链和 MAN 控制器创建/插值链中。

## ASD：时间事件数组

### 记录布局

所有字段按 v15 x86 客户端的小端序读取。

| 偏移 | 宽度 | 客户端访问方式 | 结论 |
|---:|---:|---|---|
| `+0` | 4 | `float`；与上一帧/当前时间比较 | 事件时间。执行窗口为 `previous < time <= current`。 |
| `+4` | 4 | DWORD；`switch` | 事件类型码。已见代码分派 `1,2,3,6,7`；`4/5`未在当前 switch 中处理。 |
| `+8` | 4 | DWORD；类型2 handler 的 subtype switch | 类型相关子类型/选择值，非全局统一字段。 |
| `+12` | 4 | DWORD | 类型相关参数。类型2的 subtype=1时会再按该字段分派0–3。 |
| `+16` | 4 | DWORD | 类型相关参数；类型1 handler 会读取。 |
| `+20` | 4 | DWORD | 类型相关参数；类型1 handler 会读取。 |

没有长度、magic 或版本字段；文件内容就是24字节行数组。反汇编 `0xAE0BF0` 以24递增游标，并在记录 `+0` 为负数时停止；`0xAE0C40` 把时间区间传入它。`0xAE0AE0` 按 `+4` 分派：1到 `0xAE0440`，2到 `0xAE05B0`，3到另一组模型/上下文处理，6和7分别走专用状态处理。类型2处理器中可见若干音效触发路径，但这不足以把全部类型或参数定名为通用事件语义。

### 全量资源核对

- 8,913/8,913 文件长度都能被24整除；全量扫描均找到结尾的负时间记录。
- 非终止记录的 `+4` 类型码观测计数：`0:3`、`1:172`、`2:6238`、`3:4373`、`4:15`、`6:3089`、`7:24`。这些是记录出现次数，不是文件数；类型0和4在已追的 dispatcher 中没有已证处理分支。
- 样本 `chara/01/01/0103/anim/MSA_0101_0103_08081.asd`：首条时间为200、类型6；第二条时间为 -1,000,000，符合结束记录。长度48，即一条事件和一个终止项。

**边界：** 事件参数 `+8..+20` 的意义必须按类型/子类型分开追。时间字段的单位也尚未由全链常量换算证明，不能看到200就直接标成200ms。

## MAN：骨名绑定曲线

### 通用头与记录

`0xAAFC00` 通过通用资源读取器取入文件后，直接检查magic、版本、记录数和偏移；之后按记录标签创建控制器。

| 文件偏移 | 宽度 | 当前解释 |
|---:|---:|---|
| `+0` | 4 | ASCII `0nam`（DWORD `0x6D616E30`）。 |
| `+4` | 4 | 版本；比较目标为全局常量 `dword_1108BC0=1`。 |
| `+8` | 4 | 记录数。 |
| `+12` | 4 | float参数；传入控制器初始化调用。已见控制器实现未使用，字段语义未知。 |
| `+16` | 4 | 记录区偏移。 |
| `+20` | 4 | NUL结尾字符串区偏移。 |
| `+24` | 4 | 当前解析代码未读取。 |

每条记录至少有16字节控制头：`+0` 类型标签（解析器接受 `0x00010001` 或 `0x00020001`）；`+4` float对数量；`+8` 字符串跳过数量；`+12` 在通用记录入口未解释。其后是 `count` 个8字节 float 对。`0xAAF8B0` 从记录头后16字节开始取曲线数据；对应控制器入口 `0xAAFA80` 按 `count*8` 推进数据游标。字符串游标按 `+8` 指示的数量跳过NUL结尾名称，再以当前名称调用 `0xBEB170` 做模型骨名映射。`0xAAFB50` 使用每个float对的第一个值查时间段，并把第二个值作为插值值参与更新。

### 官方37份文件的实际变体

全量扫描结果：37/37 均80字节、magic `0nam`、版本1、记录数1、记录区偏移28、字符串区偏移64。唯一记录均为：

- 标签 `0x00020001`；
- 曲线点数2；字符串跳过数0；记录头 `+12` 为0；
- 两个float对：`(0, -0)` 与 `(1000, -4)` 或 `(1000, 1)`；
- 名称表唯一字符串为 `Caterpillar`；末尾补齐到80字节。

第二点值 `-4` 出现在18份，`1` 出现在19份。`0xAAFB50` 插值后会写入宿主对象 `+512/+516` 附近的运行状态，但在当前证据链里尚未把这些宿主偏移对应到有业务含义的命名字段。文件名中的动作号只适合回连 `motionlist.csv`，不能单独证明该曲线值控制的具体骨骼或效果。

## 调用链证据（v15 IDB）

### ASD

1. `0xAE4980` 构造 `.asd` 路径，并调用资源请求 `0xAEF750`。
2. 动作更新器 `0xAE4EC0` 在 ASD 标记满足时构造当前动作路径并调用 `0xAE0D50`。
3. `0xAE0D50` 清理旧状态、请求原始文件到运行对象，再由 `0xAE0560` 将游标复位到数据开头。
4. 时间推进经 `0xAE0C40→0xAE0BF0` 扫描事件；`0xAE0AE0` 分发，`0xAE05B0` 等是类型 handler。

### MAN

1. `0xAE4B30` 构造 `.man` 资源名并调用通用资源请求 `0xAEF750`。
2. 动作更新器 `0xAE4EC0` 拼出 MAN 路径后调用 `0xAAFC00`。
3. `0xAAFC00` 检查 `0nam`、版本及类型标签，创建 `CUAnimContoroller`/`CVAnimContoroller` 控制器。
4. 控制器曲线更新例程 `0xAAFB50` 按时间在float对之间查段并插值。

动作表把 ASD/MAN 标记与动作号连接起来的依据见 `serverv/docs/R001-失败复测与客户端行为复核.md`（motionlist反汇编复核）；正式文件统计只取 `unpackdat/chara/**`。以上均为只读 IDA 分析，没有修改 IDB 或客户端。
