# v15 机体预览相关取证

本记录限定机体预览工具所需行为：机体模型/动作、手工挂载武器，以及可手工选择的机体/武器特效资源。分析使用 `ida-pro-mcp` 加载的 `GundamOnline_CHINA_v15.exe.i64`；未据此推测服务端应发出的字段，也不把任意整数当成特效资源键。

## 已确认的机体特效资源调用

- 地图特效以外，客户端机体状态处理也会创建 `CPrjFxObject`。`sub_48A760` 的交叉引用包括 `sub_4F6190`、`sub_4F6490`、`sub_4F67C0`、`sub_4FB540` 和 `sub_493540`；这些调用位于机体状态/移动处理路径。
- `sub_48A760` 从状态记录取得一个效果资源名，最多尝试 3 组、每组左右两个变体；每个候选由两位编号改写而来。它创建 `CPrjFxObject`，设置机体当前位置和方向，并启动对象。精确字段来源、左右变体语义和两位编号规则仍待逐项核实。
- 状态处理函数 `sub_493540` 中能看到明确的本地资源路径 `fx/06/PP_06_046_03.vra` 与 `fx/09/PP_09_122_03.vra`，随后经 `sub_AB4A70` 请求对应资源。该段尚未确认创建对象的具体类，也不能泛化为所有机体的推进/射击绑定。
- `sub_AB7A40` 是地图 `fx_objects` 处理器，按效果名生成 `fx/%02d/PP_%s.vra`。它属于地图对象路径，和上面的机体状态调用分开记录，不拿它替代机体绑定分析。

## PP 特效 VRA 的可见结构

资源样本 `fx/01/PP_01_001_00.vra` 含 `Target`、`Header`、嵌套 `Plug`、`Object` 与 `Sprite`。该 Sprite 声明了 `file="fx/image/PT_01_001_00.png"`、尺寸、颜色、billboard、blend、`anim_type` 和 `anim_uv`；文件头另含帧数与循环字段。这些字段可作为预览器实现输入，不需要先猜一个武器或机体特效 ID。

v15 对象配置读取器 `sub_C508E0` 读取 `billboard_x/y/z` 并组合方向标志；`sub_C50A60` 读取 Sprite 的大小、颜色、若干开关、`anim_type` 和 `anim_uv`。因此特效预览需要按 PP 文件中的 Sprite 配置与引用图片构造，而不是把 VRA 当普通静态模型加载。`anim_type` 各枚举值和运行时 UV 推进/时间曲线还未完成逆向，当前不能宣称已有准确粒子播放。

图片对象的加载路径也已互证：`sub_C520B0` 先调用 `sub_C51F10` 建立图像/对象资源，再由 `sub_C50A60` 读取对象图像字段并初始化渲染资源；`sub_C51F10` 使用 `sub_C51B00` 解析输入，`sub_C51B00` 中可见 `.dds`、`.png`、`.tga` 三类扩展名和对应资源提供器分支。v15 的 `sub_C4C910`、`sub_C4DC90` 都调用 `sub_C520B0`。正式 PP 样例中的 `Sprite` 与 `Particle` 节点均含 `file`/`dims` 字段，因此预览器将两类节点作为静态图片引用入口；汇编链仍不证明帧推进、透明混合或 billboard 的最终渲染行为。

粒子核心运行时已用于制作受限的时间点预览，但不代表客户端逐像素复现。v15 `sub_C51740` 按键读取 `emit_count`、`emit_cycle`、`emit_type`、`emit_size`、`life/life_rnd`、`fade_in/fade_in_rnd`、`fade_out/fade_out_rnd`、`move_type`、`move/move_vel/move_acl` 及五个布尔字段。`sub_C4FB50` 与 `sub_C4FE60` 各读取九个 vector3：`pos/pos_rnd`、`pos_vel/pos_vel_rnd`、`pos_acl/pos_acl_rnd`、`rot/rot_rnd`、`rot_vel/rot_vel_rnd`、`rot_acl/rot_acl_rnd`、`scale/scale_rnd`、`scale_vel/scale_vel_rnd`、`scale_acl/scale_acl_rnd`；前者为基值，后者为随机范围。`sub_C4D4C0` 遍历粒子池，按粒子出生时刻初始化实例变换；它调用 `sub_C50D40` 按 `emit_type` 生成点/线/面/体等发射位置，再乘到实例变换中。`sub_C4F610→sub_C4F3C0` 对九组三维工作参数分别按基值和随机范围生成实例值。`sub_C4D910` 推进粒子时间并清理超出寿命的实例。上述调用没有证明工作曲线插值或 `anim_uv` 的播放公式；不得再把 `sub_C50D40` 解释为 UV 动画函数。

控制台现在解析 PP 中全部可读 Sprite/Particle 图片，并允许在 `Header.frame` 时间轴上选取帧。视图近似计算 plug 时间窗、发射批次、数量、寿命、位置/速度/加速度、缩放、Z 轴旋转和淡入淡出。角度按正式资源中的度数换算；随机数采用工具内固定种子。`emit_cycle` 分批时序和 plug 事件仍近似，二维合成把 X/Y 当平面坐标，只把绕 Z 轴的旋转投影到图片平面，不复现三维 billboard、客户端 blend、颜色/Scale Work 曲线或 UV 动画，也不推断粒子空间与实际世界单位的换算。当前单文件预览会列出未解析的 Sprite/Particle 图片路径，便于区分资源缺失和预览器解析问题。正式 FX VRA 扫描到 54,663 个 Sprite/Particle 节点，其中 53,211 个 `anim_type=0`、1,452 个 `anim_type=1`；现阶段每个可读引用图均进入合成，未解析引用仍不会借用其他图片。

正式 `fx/` 下 6,267 个 PP 文件有 53,595 个 Sprite/Particle 节点，节点均含 `file` 字段，其中 4 个字段为空。按当前路径规则统计其余 53,591 条图片引用：53,455 条已解析、136 条未解析，未解析项分布在 17 个非空路径；PP 图片审计未发现同名内容冲突。另，全部 `fx/` VRA（不只 PP）共 54,663 个 Sprite/Particle 节点。

## 控制台当前支持范围

- 机体 DXG/VRA 与 MRB 动作可直接加载；机体档案的挂载资源可以手工填路径、变换和骨骼，并保存。
- 武器与弹药标签首次打开时会索引正式 `item/` 目录下的全部 DXG/VRA/DDS/PNG/TGA，支持按资源路径搜索并逐项预览；不会只展示被当前档案 ID 启发式命中的小部分 item。DXG 仍按同目录的 `EZ_*.vra` 精确关联材质。item 目录中的 MRB 暂不作为武器模型动作预览，因为当前控制台的 MRB 路径绑定的是已载入机体模型，不能据此正确预览 item 动作。
- 机体预览本身就是空场景挂载空间；载入机体和切换 MRB 后会恢复已保存的手工模型挂载。
- FX 标签列出 `fx/` 下 DXG/VRA/DDS 与 PNG/TGA 图像。资源清单可记录数字特效 ID，也能展开显式 `fx/.../PP_*.vra` 路径的资源依赖；没有确证的 ID→PP 文件映射，不会自动代填。
- FX 资源按正式 `settings/fx.csv` 的 `类别 + 唯一ID → 效果路径` 在条目上标注，重复路径会显示全部目录键，用户可以按表中 ID 搜索并打开对应 PP。v15 启动路径 `sub_A1E290→sub_AD3A50` 明确打开 `./settings/fx.csv`；其回调 `sub_AD3400` 读取每行前三列，并由 `sub_AD2F20` 按前两列建立有序键。因此这里把类别/唯一 ID 当作 FX 目录键有客户端依据。该键不等于机体档案里的某个数字字段；在客户端绑定链闭合前仍保留为独立的资源目录信息。
- 正式 `settings/str_table.txt` 把 `settings/effect_se.csv` 列为音效表，`fxoff.csv` 项带注释；其中没有 `fx.csv` 的客户端字段映射。因此这里只把 `fx.csv` 用作可核实的资源目录，不把字符串表或 CSV 行号解释成机体 FX 绑定。
- 选择 PP VRA 时，控制台解析全部带 `file` 和 `dims` 且图片成功读取的 Sprite/Particle 节点；时间轴以 Header 帧数选择合成时刻。如果 PP 没有可读图片但含 `Model` 节点，会跟随首个 Model 的 VRA `file` 到其 `geometry` 并显示静态 DXG。该回退只显示首个 Model，也不播放关联 Work 变换；其他直接引用的 VRA/DXG/DDS/PNG/TGA/MRB 文件仍列入 FX 标签，供逐项检查。点击“挂载”仍只将当前选中资源作为一个可调位置/旋转/缩放、可选骨骼的平面加入机体空间，并写入现有 mounts 档案；该平面采用工具 alpha 混合。
- 资源引用按 unpackdat 的虚拟根路径解析。正式 VRA 有 558 个以 `/` 开头的 DXG geometry 引用、1,285 个以 `/` 开头的 DDS 贴图引用，以及 171 个以 `/` 开头的 FX 图片引用；旧的 Windows 路径拼接会把这些引用变成盘符根路径，丢失用户选择的资源根目录。现在统一先去掉虚拟路径开头的斜线，再拼接已选根目录。正式资源中对应文件分别找到 554、1,283 和 161 个；缺失项继续报告为资源缺失。
- PP 时间点视图是给资源核查使用的二维近似合成，不是客户端预览器的替代实现。随机种子、发射分批精确时序、颜色/Scale Work 插值、旋转、billboard、UV 动画、客户端 blend 和世界单位仍待闭环；汇编确认一个字段的读取位置，不足以证明该近似与客户端画面一致。

## 静态建筑与炮塔 DXG 预览修正

- 当前 v15 IDB（端口 13338）中，`sub_C4E780` 读取 VRA 的 `geometry` 和 `material_set`，`sub_C19320` 遍历网格并读取 `name`、`lod0` 与 `material_id`。正式 `world/object/40/attr/OZ_40_hl_mainbase01A.vra` 的三个可见网格正好按材质 0/1/2 关联三份正式 DDS；同一 VRA 的 `MeshBV` 标记 `no_render=1`、材质 3 无贴图。
- 正式炮塔样例 `chara/06/02/0201/model/BAM_0602_0201_01.dxg` 对应 `attr/BAZ_0602_0201_01.vra`；VRA 网格 `BAM_0602_0201_01` 指向材质 1 和 `BAT_0601_0201_01C.dds`。按 DXG 打开时会按正式目录中的配对规则生成属性 VRA 名称：`MSM→MSZ`、`BSM→BSZ`、`BAM→BAZ`、`EM→EZ`、`_EM→_EZ`、`MAM→MAZ`、`PM→PZ`、`PLM→PLZ`、`UM→UZ`、`OM→OZ`、`FM→FZ`、`SM→SZ`、`OPM→OPZ`、`EVM→EVZ` 和 `DM→DZ`。此前短前缀的比较长度写错，导致 `EM/OM/FM/PM/UM/SM/DM` 实际没有转换；现在按前缀起始匹配修正。全树模型目录抽样核对中，主要类别的同目录配对 VRA 命中数为：OM 6334/6360、EM 2907/2909、FM 2552/2557、UM 1082/1082、MSM 751/752、PM 744/747、BSM 479/502、BAM 332/340、SM 75/75、MAM 52/54、PLM 32/42、OPM 21/21、EVM 10/10、DM 2/2，以及 FX `_EM` 8/8。
- 预览器现在遵守网格级 `no_render`，不再把隐藏碰撞网格画出来；没有精确材质/贴图时也不再借用首张已加载 DDS。材质查找按 VRA 网格名和材质 ID 精确关联；贴图路径先做大小写与斜线规范化，然后查找精确路径和全库唯一的路径后缀。资源审计还发现一些 VRA 的目录写错但 DDS 文件名可用：现在只在同名候选只有一份，或所有同名候选字节完全一致时才关联，并在根查看器诊断中标记这一回退；同名内容不一致时仍报告未解析。机体控制台也按相同的唯一/相同内容条件回退。
- DXG 子网格现按 v15 客户端装配链逐名匹配 VRA：只绘制 VRA 中存在的精确 mesh 名、具有 `lod0` 且 `material_id` 能命中材质表的网格，并跳过 `no_render`。移除了 `_GND_01` / `_LOD1` 名称过滤；正式资源审计确认有 3 个 `_GND_01` 网格名被 VRA 显式绑定为可见 LOD0 材质，因此此前按名称跳过会误删有效部件。没有 VRA 的原始 DXG 仍可用无材质方式查看；配对 VRA 存在但网格未绑定时不再把未绑定形状当可见部件。
- 桌面查看器此前只把 DXG chunk type `1` 当作网格块；地图场景导出流程已确认 world-field DXG 还会用 `0x201` 编码同一网格块布局。现在根查看器解析器直接接受 `1` 和 `0x201`，保留原始 DXG 的名称表，从而继续按配对 VRA 找到正确 mesh/material 绑定，不需要先改写资源文件。
- 贴图解析遵守 VRA 的材质槽边界，分别读取 `s_base`、`s_mix` 与 `s_gloss` 中的 `texture`。IDA `sub_C18120` 的三项绑定表 `off_110C90C` 经只读内存核实，顺序为 `s_base`、`s_mix`、`s_gloss`；函数从 `texture` 参数块最多读取三项并按此序绑定。正式资源同时使用嵌套 `{s_base (texture string[1] "...") }` 与 `(s_base string[2] "texture", "...")` 两种编码；后者此前漏读。DXG 顶点记录的 UV0/UV1 索引现都解码，`s_mix` 预览可使用第二套 UV。预览器用固定功能 alpha 混合近似原版 mix 材质，按 Direct3D 9 的纹理 alpha 公式组合 mix 与 base；原版 `.mtrl`/FX 着色器没有在查看器中复现，Gloss 只解析和审计，暂不参与绘制。
- 两个 3D 预览器现都将 VRA 的 ambient、diffuse、emissive、双面、alpha test 与贴图混合属性传给 D3D 材质状态。控制台预览此前只传贴图/混合标志，忽略材质颜色光照值，现已与主查看器的材质输入对齐；完整原版 shader 仍不在工具中复现。
- 场景静态对象（建筑、炮塔、地图模型）的贴图读取此前绕过同名安全恢复，只尝试 VRA 原路径；这会造成同一套 DXG/VRA 在资源列表可预览、作为场景对象载入时却无贴图。现在场景对象也统一走路径、唯一同名和同内容同名恢复，并在状态栏报告未解析及恢复计数。FX/VRA 依赖清单也使用同一解析器，标明安全同名恢复，避免已恢复的贴图仍被清单误报为缺失。
- VRA 引号值周围与路径目录段两端的空白现在会在解析后清理，再用于 geometry/材质文件查找；路径段内部内容不做模糊匹配。控制台也拒绝把盘符绝对路径或 `..` 路径拼到所选资源根之外；旧绝对路径仍可按唯一或同内容 basename 规则恢复。
- 对 texture 子目录名为四位资源 ID、但文件名中同一 ID 写错的路径，查看器现在尝试用目录 ID 替换同目录文件名中的四位数字；只在候选文件唯一时恢复。正式资源审计因此修复了 5 条引用（4 个不同路径），包括 `chara/01/79/0101/tex/` 中 VRA 引用 `MST_0179_1001_01Ca.dds`、而正式图像名为 `MST_0179_0101_01Ca.dds` 的一例。
- 正式机体 VRA 还使用紧凑旧式 BST 键（例如 `BST_03_3101_01C.dds`），但相应的 `chara/03/31/0101/tex` 只提供按完整资源目录命名的 `BST_0331_0101_01C.dds`。查看器只在类别、机体子目录编号、变体编号能逐段重建旧键且目标文件正好位于同一个 `tex` 目录时恢复；不把 `chara/03/04`、`03/09` 等近似名称映射到相似贴图。本规则在正式资源中恢复 76 条引用（2 个不同路径）。
- item VRA 有一条 `EM_12_9301_01C .dds` 引用，而同目录正式图片是 `ET_12_9301_01C.dds`。查看器会先清理扩展名前空白，再且仅在 `item/<类别>/<编号>/tex` 路径编号和文件名中的 ID 完全相同时，把材质前缀 `EM_` 修正为 `ET_`；正式资源审计恢复了这 1 条引用。其它 item 文件名不匹配没有按同目录“只剩一张图”来猜。
- 通用 DXG 加载路径按上述正式配对规则寻找同名属性 VRA，不会用同目录第一份 VRA 顶替。直接选择没有 `geometry` 字段的属性 VRA 时，也会按反向前缀配对找同名 DXG；只有正式配对路径存在才加载，避免把场景里的另一个模型误接进来。
- 可复跑扫描脚本 `tools/audit_viewer_assets.py` 按 `s_base`、`s_mix`、`s_gloss` 分别审计。当前正式资源有 67,543 条 base 贴图引用（296 条未解析、50 条同名歧义）和 6,077 条 mix 贴图引用（4 条未解析、4 条同名歧义）；base 有 5 条目录 ID 文件名修正、76 条 BST 目录键修正、1 条 item 材质前缀修正，以及 4 条唯一/同内容跨格式恢复。未发现 gloss 贴图声明。base 的 9,812 条不同路径中，9,659 条精确存在、4 条按跨格式同名恢复、4 条按目录 ID 修正、2 条按 BST 目录键修正、1 条按 item 材质前缀修正、27 条按唯一同名文件恢复、31 条按同内容同名恢复，30 条仍有冲突，52 条未解析。冲突与缺失项不会借用不相干的纹理。完整分槽路径分类写入 `viewer-asset-coverage.json`。
- 报告另列 unresolved/ambiguous 的代表绑定链，包含 DXG、精确网格名、material ID、槽位、引用路径和来源 VRA。当前样本表明未解析项分别落在具体炮塔、FX、item 和 F16 岛屿材质上；因此能区分“关联错了”和“正式贴图树里没有该图”，并保留歧义候选而不随便代入。
